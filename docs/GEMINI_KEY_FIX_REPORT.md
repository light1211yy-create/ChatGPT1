# Gemini APIキー「未設定」：調査・修正報告

基準：GitHub mainから取得した`db9ef4e8e56862237e17a9f4daf70fe5c18cafab`。専用ブランチ`fix/gemini-key-loading`。実API通信・実キーの取得・本人のsecrets.tomlの参照は行っていない。

## 原因の切り分け

**Windows本人環境の単一の原因は未確定。** Codexからその設定ファイル・環境変数を参照できず、本人用診断の結果待ち。コードから確定できた問題は以下。

1. 旧read_api_keyは空白だけの環境変数もtruthyとして返す。正しいファイル側のキーを隠し、生成器のstrip判定で「未設定」になる。架空のキーと空白環境変数で、SDKへ進む前に同じエラーを再現した。
2. StreamlitSecretNotFoundErrorを空文字に置き換え、ファイル不在・TOML構文エラー等を区別できない。型不正も空文字になり、すべて同じ「未設定」に見える。
3. st.secretsはホーム・作業ディレクトリ・主スクリプトの秘密設定を集約し、キャッシュしてトップレベル値を環境変数へ反映する。Streamlit自体も起動時に読み込むため、アプリの3確認とは別に読まれる問題がある。

Streamlit 1.51はスクリプト基準の場所も探索するため、作業ディレクトリだけが原因とは断定しない。start_windows.bat／setup_windows.batは元からcd /d "%~dp0"でプロジェクトへ移動しており、この部分は維持する。別フォルダへの設置、secrets.toml.txt、セクション内のキー、空欄、BOMや文字コード等は実機の診断で確認する。

## AQ形式とSDK

既存の認証キー読込・生成処理に、AIza限定の正規表現・先頭文字・長さ制限はなかった。旧AIza検出は企画データの漏えい防止用であり、認証キーの許可判定ではない。今回AQ形式の漏えい検出も追加した。

インストール済み公式google-genai 3.0.0のソースはapi_key引数を受け取り、strip後にx-goog-api-keyへ設定する。AQを先頭文字で拒否する処理は見つからなかった。架空のAQ／AIzaをファイル・環境変数から生成器・実SDK・MockTransportへ渡し、選ばれた値がヘッダーへ届くことを確認する。キー形式だけで有効性・課金を判定せず、AQを推測でBearer認証へ変換しない。

[Google公式APIキー仕様](https://ai.google.dev/gemini-api/docs/api-key)は、通常サンドボックスで接続不可、環境プロキシ経由でもCONNECT 403で本文を取得できなかった。**AQ形式の現行公式仕様・実サービスでの認証受理は未確認。** モックはGoogleでの認証成功を証明しない。現状の「未設定」はSDK呼出し前の問題なので、SDK更新の根拠はなく3.0.0を維持する。

## 修正

- studio/key_config.pyに読込を集約。app.pyと同じプロジェクトの.streamlit/secrets.tomlを優先し、不在時だけGEMINI_API_KEY環境変数を使う。ホームや別作業フォルダのキーは取り込まない。
- **優先順位は旧版の環境変数優先から変更。** 古い環境変数がプロジェクトの明示設定を隠さないようにする。ファイルが空欄・不正でも別キーへ自動切替せず、理由を表示して停止する。
- ファイルは承認後だけ読み、Streamlitのキャッシュは使わない。.streamlit/config.tomlのsecrets.files=[]で起動時の自動読込・環境変数上書きを無効にする。MAKASEの他の機能はst.secretsを使っていない。
- UTF-8／UTF-8 BOM／CRLFに対応。型・トップレベル・空欄・構文・読取権限を検証する。TOMLやOSの生エラーを表示せず、固定の日本語エラーへ変換する。
- prefix／長さの制限なし。前後の空白は除き、HTTPヘッダーへ不正な改行等が入る場合は拒否する。キーの有効性・権限・課金は推測しない。
- AQ形式が企画メモ・過去テーマ名に含まれれば、SDKへ進まず拒否する。認証用キーそのものにこの企画データ用フィルタを適用しない。
- 3確認、3.8／MEDIUM、手動3.5-Lite、Thinking設定、SDK・依存・DB・Windows起動バッチは維持する。

「ファイルなし」ならapp.pyの直下にある.streamlit/secrets.tomlか確認する。secrets.toml.txtの表示があればExplorerで拡張子を確認する。「構文不正」なら本人のローカルエディタで引用符・文字コードを確認する。「トップレベル項目なし」ならキーをセクションより前へ置く。ファイルを消去・作り直す必要はなく、他の設定を保持する。APIキーの有効性やプロジェクトのBilling状態は、この診断では判定しない。
