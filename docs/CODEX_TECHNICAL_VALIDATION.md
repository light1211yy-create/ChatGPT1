検証日：2026-11-04（日本時間）。目的は追加課金なしで10テーマを実AI生成し、成功後だけ既存アプリに接続すること。前提資料は`AGENTS.md`、`docs/PROJECT_SPEC.md`、`docs/AI_OPTIONS_REVIEW.md`。

## 結論

**クラウド環境では追加費用0円という実行条件を確認できず、実AI推論は実行していない。10案生成とアプリ接続も未達である。** ChatGPT方式の認証があることと、本人のPlus契約内で追加クレジットを消費せずに実行できることは別である。

この前提を緩めて試すことや、APIキーへの切り替えはしていない。Phase 1・Phase 2のアプリ、SQLite、承認履歴、無料テスト生成はそのまま保持した。接続用のモード切り替えUIは、実AI生成成功後に行う条件付き作業なので未実装。

## 2. 今回追加した検証ツール

`scripts/codex_theme_probe.py`はアプリと独立した単発検証ツール。通常実行は状態確認だけで、推論を開始しない。認証や課金設定を変更する機能はない。

推論には`--generate`と、本人による`--confirm-no-paid-credits`の明示指定が必要。それに加え、次をすべて確認できなければ実行を停止する。

- ChatGPT方式の認証とPlusプランである。
- APIキー・直接トークンの別認証経路が環境変数に設定されていない。
- 機械可読の利用枠取得が成功し、両方の利用枠に残量がある。
- 追加クレジットなし・無制限クレジットなし・有料クレジット残高ゼロの状態が報告される。
- 本人が追加クレジット購入・自動購入を利用しないと確認した。

CLIによって取得できる状態やプロトコルは異なり、不明なら停止する。全CLI版に対応するとは保証していない。残量チェック後の他の操作による枠消費や、本人が別途行う課金設定変更までは制御できない。確認フラグだけで利用条件が証明されるわけではなく、取得に失敗した状態でフラグを付けても停止する。

生成時は正規ChatGPT方式とOpenAIプロバイダを指定し、別のユーザー設定を読み込まず、一時作業ディレクトリ・read-onlyサンドボックスを使用する。シェル・編集・MCP・アプリ・フック等を無効化し、ツールも外部アクションも使わないよう指示する。権限を全面解除するオプションは使わない。非対応のCLIオプションがあれば成功扱いにせず停止する。

デフォルト180秒、指定可能な上限300秒。タイムアウト時は自分で起動したプロセス群を終了する。生の標準エラーや生成イベントログは保存しない。認証トークンを渡す引数やAPIキーは要求しない。CLI自身の正規ログイン管理は本人が行う。

## 3. 出力の形式と保存

条件は現在の日本時間の日付、マカセ、日本在住18〜34歳、女性約55%・男性約45%、全国のホテル・旅行・レストラン、写真映え、季節・イベント・旅行需要、フォロワー増加・保存重視。

生成元のJSONは`themes`配列10件で、各件のキーは次のとおり。

```text
title              投稿テーマ
category           既存のCATEGORIESのいずれか
score              0〜100の整数
reason             企画理由
outline            投稿構成
target             対象視聴者
posting_period     おすすめ投稿時期
information_basis  季節に基づく提案（最新Web未確認）
```

既存の`ThemeDraft`にない対象者・投稿時期・情報区分は、検証後に`reason`へ明示して変換する。元の構造化された値も結果JSONに保持する。既存の必須項目・文字数・スコア・重複チェックを通った結果だけを、新しいJSONファイルへ排他的に保存する。SQLiteへは書き込まない。既存ファイルやDBを出力先に指定しても上書きしない。

Web検索は無効。最新トレンドや現在の価格・開催状況を確認済みと表現しない。季節に基づく提案であることを固定の情報区分で示す。過去テーマは任意のJSON配列を入力でき、同一文字列の重複を拒否する。類似内容の重複は別途人が確認する。未入力の場合は過去テーマとの重複回避を未確認として扱う。

成功結果には`mode: real_ai_codex_cli`と日時が付く。今回は成功結果ファイルは存在しない。ユニットテストで用いる模擬生成を実AIの結果として配布していない。

## 4. Windowsで本人が行う手順

最初にPhase 2（GitHub mainの`ee915c2`以降）を更新済みのフォルダを用意する。更新・検証前にアプリを停止し、SQLiteと関連ファイル・既存ソースをバックアップする。検証ZIPの`scripts`・`tests`・`docs`の内容をそのフォルダへ追加する。`.venv`・`data`・秘密設定は置き換えない。

1. [公式Codex README](https://github.com/openai/codex#installing-and-running-codex-cli)からWindows用ネイティブCLIを導入する。このツールは`codex.exe`を使い、npm等の`.cmd`ラッパーを直接起動しない。
2. PowerShellで確認する。

```powershell
Get-Command codex.exe
codex --version
codex login
```

3. 本人がブラウザで正規のChatGPTアカウントへログインする。APIキー・アクセストークンでログインする選択肢は使わない。ログインURLの認証コード、トークン、セッション情報をチャットへ貼り付けない。
4. ChatGPT／Codexの利用状況画面で契約内の利用枠、追加クレジット残高、購入・自動購入の設定を本人が確認する。追加クレジットを持っている場合も、この厳格な検証ツールは推論を止める。検証のために契約や購入設定を変更する必要はない。
5. プロジェクトのフォルダで確認専用のコマンドを実行する。

```powershell
.\.venv\Scripts\python.exe scripts\codex_theme_probe.py
```

6. 状態が取得でき、Plus・残り利用枠・追加クレジットなしを確認できた場合だけ、本人の確認を伴って単発生成する。

```powershell
.\.venv\Scripts\python.exe scripts\codex_theme_probe.py --generate --confirm-no-paid-credits --timeout 180
```

出力先は既定で`data/codex-theme-probe.json`。既存ファイルは上書きしないので、再実行時は別名の`--output data/codex-theme-probe-2.json`を指定する。必要に応じて`--past-themes data/past-theme-titles.json`を付ける。入力は`["過去のテーマ1", "過去のテーマ2"]`のような文字列配列で、認証ファイルやDBファイルは指定しない。

停止したら制限を外して進めず、安全なステータスと停止理由だけを確認する。スクリプト出力のプランや利用枠の要約は共有できるが、認証情報やCodexの生ログを共有する必要はない。生成成功時は10テーマの内容と情報区分を確認し、その後にアプリ接続の実装へ進める。今回のWindows手順・推論・結果保存はWindows実機未検証。

## 5. テストと既存データの保護

- 既存44件のテストは保持。
- 追加テストはプラン不明、API経路、利用枠取得失敗、クレジット有り、残量なしでの推論阻止、本人確認必須、ステータスの値の制限、権限制限、JSON検証、既存ファイル保護、エラーの秘匿、タイムアウト終了を確認する。
- モックによる正常な結果取得・変換テストは、実AI推論成功の証拠ではない。
- 既存のStreamlit画面・生成器・SQLite処理は変更しない。検証のためにユーザーの実DBを変更しない。
- 自動実行やスケジュールを有効化しない。GitHubへのpushは行わない。

## 6. 将来の週次自動実行と無料代替

CLIの非対話機能だけで、週次の契約枠や無人稼働を保証できない。Windowsの電源・スリープ、認証期限、枠切れ、実行時間、CLI更新とプロトコル互換性、再試行・重複防止が課題になる。テーマ承認と完成物承認は引き続き人が行い、TikTokへの直接公開はしない。

利用枠を正規の方法で確認できない、またはCLIが用途に適合しない場合の第一代替は**Ollama＋無料のローカルモデル**。PCのRAM・GPU・空き容量と日本語品質を確認してから、クラウドモデルを使わずローカルAPIで検証する。課金サービスの無料枠やOpenAI APIへ自動で切り替えない。

PC性能が足りなければ、既存Plusの画面で本人が生成し、構造化JSONを手動で受け渡す方式を次の候補にする。この手動取り込み画面も今回の条件付きアプリ実装には進めていない。
