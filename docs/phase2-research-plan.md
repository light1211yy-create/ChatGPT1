# Phase 2：施設リサーチ機能の実装準備

検討日：2026-11-04（日本時間）。本書は開発方針です。現在は初期実装として、承認済みテーマからの施設候補の手動登録・比較・編集、項目別出典、写真候補と許諾状況・期限のSQLite保存を実装しています。自動収集・写真取得・外部投稿は実装していません。

## 追加費用0円で始める方法

既存のPython・Streamlit・SQLiteを使い、施設情報の手動登録・確認・承認から始めます。施設公式サイトや、再利用条件が明確な自治体のオープンデータを候補の情報源とします。無料で閲覧できることと、転載・自動取得・商用利用の許諾は別に確認します。

初期実装では、利用者が通常のブラウザで公式情報を確認し、事実情報と出典URL・確認日を入力します。地域・予算・施設種別で候補を絞り、投稿用の事実メモを作ります。施設紹介文は丸ごとコピーせず、確認済み事実に基づき自分の言葉で作成します。

有料AI・有料検索API・課金の可能性がある地図API・有料クラウド・予約API契約は不要です。無料枠にクレジットカードを登録して従量課金する設計も採用しません。既存PC・通信環境と人による確認作業は必要です。無料モデルを後から接続しても、施設の存在・価格・営業時間をモデルの推測で補完しません。

## 正確性を確保する設計

| 保存対象 | 確認方法・扱い |
| --- | --- |
| 施設名・住所・公式URL | 施設の公式サイトを優先。名称と住所で同名施設を区別する |
| アクセス・営業時間・休館日・設備 | 項目ごとに出典URL、確認日時、確認者、未確認／確認済み／再確認必要を保存する |
| 料金 | 宿泊日・人数・部屋・食事・税込／税抜・手数料・キャンセル条件・確認日時と一緒に記録する。料金だけを固定情報として扱わない |
| 予約状況 | 手動で確認した時点の参考情報とする。在庫や空室を保証しない。予約・購入は実行しない |
| 出典間の不一致 | 自動で片方を採用しない。公式情報や施設への確認で解決するまで「再確認必要」にする |
| 投稿原稿 | 確認済み情報を参照して作成し、公開前に人が再確認・承認する |

料金・空室は24時間経過で再確認を促す初期案とし、施設情報も投稿前に再確認します。24時間以内なら正しいという保証ではありません。未入力は「不明」と表示し、推測で埋めません。登録・修正・承認の履歴を保存し、リサーチ承認と写真の権利承認は別々に扱います。

## 写真素材の利用許諾

最初は「写真なしで下書きを作る」か「自分で撮影し、撮影・公開に必要な許可を得た写真」を使います。施設公式サイトや予約サイトに載っている写真も、自由に使えるとは扱いません。スクリーンショット、画像URLの直リンク、クレジット表記だけでの転用も許諾の代わりにはしません。

施設・権利者から提供を受ける場合は、少なくとも次を資産ごとに記録します。

- 権利者、写真の出所、許諾を示す文書・参照先と確認日。
- TikTokなど対象媒体での商用投稿、広告利用の可否。
- トリミング、文字重ね、動画への組み込み等の編集可否。
- クレジット表記、利用期限、再配布の可否、撤回時の対応。
- 写り込んだ人物・私有地・作品等の権利や施設の撮影ルールの確認状況。

状態を「未確認／利用可／利用不可／期限切れ」で管理し、利用可でない素材は投稿制作へ渡しません。許諾書や私的な連絡記録はGitに入れず、個人データとしてローカルで管理します。オープンライセンス画像も媒体・商用利用・改変・表示義務等を個別に確認し、条件を満たせなければ使用しません。

## 一休.com・Trip.comの利用規約への対応

公式サイト： [一休.com](https://www.ikyu.com/) ／ [Trip.com](https://jp.trip.com/)。利用する際は各サイトのフッター等から、その地域・言語・サービスに適用される最新の利用規約を確認してください。

**現行規約の本文は未確認です。** 検討日にこの環境から公式ページの読み取りを試みましたが、両サイトともプロキシの接続段階で403 Forbiddenとなり、本文を取得できませんでした。規約への適合やAPI・素材利用の許諾が確認済みだとは判断していません。

接続前に、規約URL・適用サービス／言語・規約の版や更新日・確認日と、次の判断を記録します。

| 確認事項 | 許可を確認できない場合の対応 |
| --- | --- |
| 自動アクセス、スクレイピング、複製・保存・再配布 | 自動取得しない。公式サイトの情報を独立に調べる |
| 写真・説明文・口コミ・評価の権利 | 写真・説明文・口コミを転載せず、評価も取り込まない |
| 商用・SNS投稿、アフィリエイト・ブランド表記 | 必要な許可・契約なしに素材やアフィリエイト機能を使わない |
| 公式API・データフィード | 提供条件、用途、料金、認証を確認する。0円が確定できなければ導入しない |
| 外部リンク・施設の参照方法 | リンクについても適用される条件を確認し、無断の提携表現をしない |

これらは確認項目であり、両サイトに特定の条項があると断定するものではありません。robots.txtに許可があっても、転載や利用規約上の許可が得られるとは判断しません。CAPTCHA、ログイン、アクセス制限、レート制限を回避しません。ユーザーにブラウザ操作を代行させることも、規約上の禁止を回避する方法として扱いません。

ネットワークから確認できないままでも、予約サイトのデータを一切取得しない手動リサーチ機能は開発できます。予約サイトを接続するには、通常の閲覧環境での規約確認、または環境設定で必要な公式ドメインのアクセス許可が必要です。今回、ネットワーク設定は変更していません。

## 次の実装単位と受け入れ条件

1. 施設の手動登録・編集と検索。施設、項目別出典、確認履歴をSQLiteに保存する。
2. 確認待ち／再確認必要を含むリサーチ承認画面。未知・古い・矛盾した情報を確認済みとして出さない。
3. 写真の権利情報登録と制作への受け渡し制限。未許諾・期限切れの写真を制作へ渡さない。
4. 投稿原稿と出典を並べて確認する画面。原稿生成や施設リサーチ承認から自動投稿は行わない。

初期実装のテストでは、施設・出典・写真許諾の保存と編集、写真の利用状態・期限、承認取り消し時の編集防止、競合検出、再起動後の保存、旧DBとの共存を検証します。情報の確認期限通知、出典の矛盾検出、リサーチ自体の承認、画像の制作への受け渡し、原稿と出典の照合は今後の開発対象です。予約サイトへの自動アクセスや外部API接続は含みません。Phase 1はGitHub保存済みでWindows起動成功のユーザー報告があります。このPhase 2更新版のWindows実機検証とGitHubへのpushは未実施です。
