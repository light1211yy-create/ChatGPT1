## 4. 最も現実的な方法

**短期の第一候補は「既存Plusの契約内で使うCodex CLIを、生成専用に小さく検証する方法」**とする。公式READMEがChatGPTログインでPlusに含まれるCodex利用を案内しており、非対話・JSON出力の機能をこの環境のCLIでも確認できた。新しい有料APIも大きなローカルモデルも必須にせず、自動化に近づけられる点が理由である。

ただし、これは利用枠内で動くことや品質を確認済みという結論ではない。Windowsで本人の正規ChatGPTログインによる利用権・制限を確認し、少数の企画生成を実測してから採用する。上限に達したら停止し、APIキーや追加クレジットへ切り替えない。Codexのアプリ／クラウド会話を、Streamlitから自由に呼べる無料APIとみなすわけではない。Codex CLIは実行能力を持つ開発エージェントなので、汎用の生成APIとは異なる管理が必要である。

**無人運用の長期候補はOllamaのローカル推論**。現行コードの生成器構造と接続しやすく、外部サービスの無料枠に依存しない。ただし本人PCの仕様が不明なため、特定サイズのモデルが実用速度で動くとは断定しない。Qwen3等の多言語モデルを候補に、実際の量子化・メモリ・日本語品質・ライセンスを確認する。Ollama本体のMITライセンスと各モデルのライセンスは別に確認する。

CLIの利用枠やPC性能が合わなければ、**Plusで作った結果の手動JSON取り込み**から実AI運用を始める。手動工程はあるが新規登録・API料金を増やさずに進められる。Gemini／Groq等は、現行の無料条件・制限・データ取扱いを確認できるまで予備候補とする。

## 5. テーマ企画の実装案（今回は未実装）

1. 現行の`ThemeGenerator`、`JsonThemeGenerator`、`generate_and_save()`を使用し、テスト生成を残す。生成器は本人が明示選択し、暗黙のクラウド送信・有料APIへの切り替えをしない。
2. Codex候補は、正規のChatGPT認証を使うCLIを別プロセスで呼び、最終の構造化出力だけを取得する。必要最小限の集計済み実績・企画条件だけを渡し、実DB・許諾書・個人情報・外部投稿用認証情報を入力に含めない。
3. CLIは生成専用の作業領域、読み取り制限と許可範囲、タイムアウト、終了コード確認を設定する。無人化のために権限やサンドボックスを全面解除しない。イベントJSONLと最終応答JSONを混同しない。エージェントにアプリやDBを直接編集させない。
4. Ollama候補はWindows上のループバックAPIへ接続し、ローカルモデルを明示する。JSON Schema出力・`stream: false`等で単一応答を受ける。外部のOllamaクラウドモデルへ自動送信しない。
5. 手動候補は、企画条件の出力とJSON貼り付け／取り込みを追加する。現行の件数・重複・必須項目・スコア検証を通った結果だけを、生成元を区別して保存する。
6. モデル名・実行経路・プロンプト版・日時・入力条件を記録する。例外・制限・不正応答は保存せず、回数を制限して再試行する。既存SQLiteと承認履歴は保持する。

## 6. 施設リサーチの実装案（今回は未実装）

最初は**「確認済み情報からの推薦」と「新しい事実の取得」を分離**する。

- 推薦：承認テーマに紐づく既存施設候補・出典を入力し、AIは候補ID、選定理由、参考評価、参照した出典ID、不足情報を返す。返された施設IDが登録済みで、出典がその施設に属するかを検証する。未知の施設やURLを事実として保存しない。
- 選定：5施設の採用案を本人に表示し、確定する。5件揃わなければ不足として止め、架空のホテル・価格で補わない。テーマ承認の取り消しは現在の制限を維持する。
- 取得：本人が確認した公式URL・確認日・事実を登録する方法から始める。検索を使う場合も、検索スニペットを確定情報にせず、出典・確認時点・条件を確認する。
- 将来の自動取得：対象サイトの規約と許可された方法を確認した後に、モデルとは別の取得処理で必要な公式情報だけを扱う。今回この接続処理は作らない。一休.com・Trip.comの取得許可・写真利用は未確認のままである。
- 写真：AIの「写真映え」評価と利用許諾を分ける。候補URLや画像認識結果だけで許諾済みにせず、現行の権利情報・用途・期限で判定する。写真そのものの評価には画像対応モデルと正当な取得経路の追加検証が必要。

紹介文は出典付きで確認した事実から生成し、価格条件と許諾範囲を人が確認する。Canvaへの変更、TikTokへの転送、外部公開の処理はこの検証に含めない。
